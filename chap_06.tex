\section*{Introduction}
\addcontentsline{toc}{section}{Introduction}

\paragraph{}Sprint 4 adds an optional Large Language Model enrichment layer to the generator. The previous
sprints produced coherent financial data, but several descriptive fields remained deterministic.
This sprint improves names, symbols, descriptions, account labels, account group labels, and model
labels while keeping identifiers, quantities, dates, and relationships under deterministic control.

\paragraph{}The enrichment feature is not a separate generation mode. It is inserted into standalone and
connected generation after base records are created and before final validation and SQL assembly.

\section{Sprint Design}

\paragraph{}The design of Sprint 4 isolates the LLM behind dedicated client and enricher classes. The
generation services do not ask the AI provider to create records. They create a valid base dataset
first, then ask the enrichment layer to improve only authorized text fields.

\section{Realization}

\paragraph{}The realization of Sprint 4 is implemented in the backend module \texttt{modules/llm}. The
module contains prompt builders, specialized enrichers, the service facade, and the provider client.
\texttt{GeneratorService} and \texttt{ConnectedGeneratorService} both call \texttt{LlmService} after
base generation. This gives standalone and connected modes the same enrichment behavior.

\paragraph{}The fields that may be modified are deliberately limited. For securities, enrichment can
improve names, symbols, identifiers used for display, issuer names, and descriptions. For accounts,
groups, and models, enrichment improves readable labels. The system preserves structural fields such
as generated links, account identifiers, security relationships, dates, quantities, prices,
allocations, and order references.

source of business rules. The generated dataset remains deterministic at the structural level, and
the validator remains the final authority before output.

\section*{Conclusion}
\addcontentsline{toc}{section}{Conclusion}

\paragraph{}Sprint 4 delivered optional LLM enrichment for generated financial data. The feature improves
realism when the provider is available and safely falls back to deterministic values otherwise. The
next sprint finalizes the application by adding reusable configuration management and global
workflow safeguards.
